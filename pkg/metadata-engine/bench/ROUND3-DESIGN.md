# 第三轮方案：仅供 checkpoint 使用的固定读视图

第二轮百万条阶段样本仍有约 50 ms 锁内捕获，完整复制 key/payload 带来约 319.5 MiB
临时分配。选择固定 checkpoint 视图，暂不引入跨表查询、公开 MVCC 或磁盘页索引。

## 状态与所有权

- 引擎节点和 key 在 Engine 生命周期内稳定（tombstone 不物理删除）。
- 捕获在状态锁内分配精确长度的视图数组，复制 type/key/payload/generation/tombstone
  和节点指针。key/payload 仅借用；节点的一字节原子 pinned 标志置 true。
- 视图数组保留边界 S，随后按原协议轮转 WAL 并释放状态锁，编码固定视图。
- 第一次覆盖被固定节点：原子交换 pinned=false。若旧值为 true，旧 payload 转归
  checkpoint 视图；若为 false，按原规则释放旧 payload。后续覆盖正常释放中间版本。
- checkpoint 完成或失败后，对每项原子交换 pinned=false：若旧值为 true，当前节点
  仍拥有该 payload，不释放；若为 false，写者已把旧 payload 的所有权交给视图，释放它。
- 只支持一个内部 checkpoint 视图，checkpoint_mutex 覆盖捕获、写盘、安装和视图释放。
  下一次捕获不会与旧视图释放交错，避免标志 ABA。不暴露任意长生命周期的读事务。
- 交换操作使用 acq_rel。清理不读取并发变化的节点 payload/generation，只操作原子标志
  和不可变视图。所有权交接后写者不再读取/释放旧 payload。

## 故障与并发矩阵

| 时点 | 行为与恢复 |
| --- | --- |
| 数组分配失败 | 没有 pin，没有 WAL 或数据变更 |
| 捕获完成但轮转失败 | 释放视图的 pin；必要时冻结引擎，原恢复规则不变 |
| 写快照前/中/同步失败 | 不安装新快照，释放全部 pin 和已退休旧值；旧快照 + WAL 恢复 |
| 视图释放与首次覆盖并发 | 原子交换决定唯一释放者，不允许重复释放或漏释放 |
| 连续覆盖 / tombstone / 恢复写入 | 视图仍编码 S 的旧元信息和值；当前读取得最新已确认版本 |
| 并发提交同步失败 | 引擎冻结，禁止安装快照；视图清理仍必须完整 |
| 安装后清理失败 | 已安装快照有效，旧值照常释放，WAL 清理按原协议重试 |
| 强杀 | pin 是内存状态；磁盘格式/同步边界没有改变，重放校验保持原样 |

get/scan/page 继续返回调用者拥有的副本，不改变 CAS、FIFO、可见性和同步语义。
Engine.deinit 必须等待所有调用完成；allocator 继续要求支持后台线程并发使用。

## 成本与验收

捕获仍是 O(N)，预计视图条目 64 B，节点应保持 64 B。不复制 key 和未变化 payload；
最坏情况下整个快照 payload 被覆盖时会保留一份旧值，仍受原快照逻辑字节预算约束。
新值仍受 max_live_bytes 约束，不能把逻辑额度当 RSS 上限。没有新增读放大或磁盘写放大；
每次覆盖增加一次原子交换。需要实测捕获耗时、内存、吞吐、P99/P99.9/最大停顿与重开。

先保存第二轮二进制；新增并发覆盖、失败清理及所有权测试，运行 OOM、ReleaseSafe、
SIGKILL 和混合模型验证。1 万/10 万/100 万条交替各三次，单用例 600 秒上限。
仅收益经实测确认后保留方案；长期与 NAS 验证不以短测替代。
