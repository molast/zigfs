# 第三轮优化报告：检查点固定读视图

日期：2026-11-17。独立包 `pkg/metadata-engine`，尚未接入 ZigFS。
本轮选择并实现一个候选：仅供 checkpoint 使用的固定读视图，具体设计、所有权与
故障矩阵见 [ROUND3-DESIGN.md](ROUND3-DESIGN.md)。没有实现冻结表、公开 MVCC 或磁盘页索引。

结论：保留此方案。百万条捕获停顿显著缩短，写入维护阶段的临时分配和采样 RSS 明显下降；
全流程峰值 RSS 基本不变，部分小值负载的吞吐/P99 退步，不能称为所有维度提升。

## 相同数据量，直观看时间和内存

Apple M2 Pro、16 GiB、macOS ARM64、Zig 0.17.0 ReleaseFast。
基线是保存的第二轮二进制；每条 23 B 键 + 256 B payload，插入批量 32，覆盖更新
为 8 个客户端提交单条事务。同步策略、Group Commit 和自适应维护配置均保持一致。
各档前后各三次，before/after、after/before、before/after 交替串行运行，取中位数。
正式对照关闭阶段计时和分配采样。

| 数据量 | 完整流程：之前 → 之后 | 覆盖 QPS：之前 → 之后 | 更新 P99：之前 → 之后 | 进程峰值 RSS：之前 → 之后 |
| --- | --- | --- | --- | --- |
| 1 万条 | 0.17 → 0.16 s | 92,397 → 96,554 | 162.21 → 158.50 μs | 13.6 → 13.7 MiB |
| 10 万条 | 1.59 → 1.69 s | 93,407 → 84,933 | 165.92 → 177.21 μs | 76.9 → 77.6 MiB |
| 100 万条 | 17.08 → 17.34 s | 91,442 → 88,473 | 177.42 → 184.21 μs | 759.5 → 762.5 MiB |

完整流程包含插入、读取、覆盖、分页、全量扫描、重开、手动 checkpoint 和再次重开。
峰值 RSS 包含返回给调用者的扫描副本与分配器缓存，不等于引擎常驻记录内存。
所有性能用例均为实测、单用例低于 600 秒，没有预测值。

| 覆盖更新 QPS | 91,442 | 88,473 | 减少 3.2% |
| 更新 P99 | 0.177 ms | 0.184 ms | 增加 3.8% |
| 更新 P99.9 | 1.155 ms | 1.094 ms | 减少 5.3% |
| 单轮最大更新延迟的中位数 | 70.291 ms | 43.078 ms | 减少 38.7% |
| 后台 checkpoint 次数 | 2 | 2 | 减少 0.0% |
| 更新阶段同步次数 | 125,003 | 125,006 | 增加 0.0% |
| 快照 + 剩余 WAL 重开 | 0.998 s | 0.975 s | 减少 2.4% |
| 纯快照重开 | 0.649 s | 0.637 s | 减少 1.8% |
| 手动 checkpoint | 0.517 s | 0.433 s | 减少 16.2% |

三次实际最大更新延迟（不隐藏慢轮次）：

| 版本 | 第一次 | 第二次 | 第三次 |
| --- | --- | --- | --- |
| 第二轮 | 70.29 ms | 51.26 ms | 137.23 ms |
| 第三轮 | 43.08 ms | 9.70 ms | 153.70 ms |

仍测到一次 153.7 ms 长尾，超过本轮基线三次中的最差值 137.2 ms，不能宣称所有最大停顿均改善。
百万条覆盖吞吐中位数下降约 3.2%，P99 略增；10 万条 256 B 覆盖吞吐下降约 9.1%，
P99.9 从约 355 μs 增至 644 μs。更新路径增加了原子 pin 交接，但本轮未单独分离
原子操作、调度与系统 I/O 的影响，不能把全部退步精确归因于某一个因素。

没有降低同步等级或减少提交确认要求。固定视图只影响内存捕获与回收；WAL/快照格式、
条件写入、FIFO 和错误冻结语义不变。快照回放仍是热缓存结果，不是冷盘启动保证。

## 对应瓶颈是否确实改善

下面是单独的 phases 运行，前后各一次，不混入上面的三次正式排名。

| 阶段指标 | 之前 | 之后 |
| --- | --- | --- |
| 捕获次数 | 2.00 | 2.00 |
| 捕获总耗时 | 138.30 ms | 17.29 ms |
| 最长单次捕获 | 92.74 ms | 8.73 ms |
| 状态锁最长持有（含其他操作） | 94.10 ms | 41.83 ms |

最长捕获约 92.7 → 8.7 ms，减少约 90.6%；捕获仍为 O(N)，并没有消除所有状态锁停顿。
该变化没有以减少 checkpoint 次数为前提。设备 sync、WAL I/O、长扫描仍可制造其他停顿。

## 内存到底减少在哪里

profile 为独立运行，各一次。Engine 分配量是请求字节数，不包含分配器取整/缓存、
调用者拥有的 get/page/scan 结果。RSS 是整个进程驻留内存，两种口径不可简单相减。
历史字段 `snapshot_copy_live` 在第三轮表示刚捕获的固定视图，不再是全量字节副本。

| 阶段/指标 | 之前 | 之后 |
| --- | --- | --- |
| 插入完成：引擎持有分配 | 377.1 MiB | 377.1 MiB |
| 视图刚捕获：引擎持有分配 | 696.6 MiB | 438.1 MiB |
| 整个流程：引擎分配峰值 | 696.6 MiB | 449.9 MiB |
| 更新完成：引擎持有分配 | 377.1 MiB | 377.1 MiB |
| 更新完成：进程 RSS | 701.3 MiB | 429.7 MiB |
| 全量扫描结果存在：进程 RSS | 751.7 MiB | 730.7 MiB |
| 引擎关闭：持有分配 | 0.0 MiB | 0.0 MiB |
| 引擎关闭：进程 RSS | 623.8 MiB | 627.0 MiB |

未修改的 payload 直接共享；只有快照期间首次覆盖的旧 payload 被保留。视图数组约
61.0 MiB/百万条，取代原约 319.5 MiB 的条目数组加键值副本。节点仍为 64 B，稳态请求分配
仍约 377.1 MiB。最坏情况下所有被固定值均被覆盖，会保留一份旧 payload，仍非零成本。

全量扫描仍复制全部键值，之后 allocator 保留这些内存；后续重开和手动快照又复用/申请
空间，因而全流程峰值 RSS 没有同步大幅下降。不能将“视图捕获少约 258 MiB 分配”
改写成“整个进程少约 258 MiB 峰值”。引擎关闭后跟踪分配为零，RSS 不会立即归零。

同样前后各三次中位数：

| 负载 | 更新 QPS：之前 → 之后 | P99：之前 → 之后 | 最大延迟中位数：之前 → 之后 |
| --- | --- | --- | --- |
| 1 万条 / 256 B / 1 客户端 | 16,386 → 16,768 | 89.79 → 83.67 μs | 0.32 → 0.27 ms |
| 1 万条 / 256 B / 32 客户端 | 143,702 → 145,548 | 435.96 → 371.88 μs | 0.71 → 0.44 ms |

但不能据此推断任意值大小或任意并发下都更快。

## 正确性与边界

- Debug / ReleaseSafe 各 59 项单元测试。新增原始快照旧值/旧 generation 校验、连续覆盖与
  tombstone/恢复、未变值所有权、退休旧值后的编码 OOM、并发同步失败、节点尺寸、
  32 次 checkpoint 释放与持续覆盖竞争。原有配额、损坏和所有分配失败验证保留。
- 27 个实际 SIGKILL 场景：原 22 个场景，加 5 个视图捕获后已确认修改在写完、同步、
  安装、目录同步和清理边界强杀的场景；旧快照或新快照恢复均需保留已确认事务。
- 60 秒单进程混合参考模型通过：1,052,454 个事务、16,446 次模型校验、4,686 次 checkpoint，
  3 次额度重试后继续推进，最终重开校验通过。仅 6 × 64 个键，采样 RSS 峰值约 2.75 MiB；
  不能据此认定长期无泄漏或生产成熟。
- pin 交接使用原子交换，只有第一次覆盖保留旧值；释放读视图不读取可变的当前 payload。
  checkpoint_mutex 覆盖视图全部生命周期，避免下一轮 pin 与上一轮释放交错。
- 没有新增磁盘读放大或写放大，没有公开长生命周期读事务。Engine 销毁仍要求全部调用结束，
  allocator 仍需支持后台并发使用。max_snapshot_bytes 限制覆盖的逻辑键值体积，不是 RSS 上限。
- 冷缓存、长期回收趋势、NAS/Linux 与真实断电仍未验证。第四轮不能标记为已完成。
