# 网络配置

Network 页面用于设置 ZigFS 的访问地址、S3 寻址方式、可信代理及服务监听地址。
入口为 **System Setting → Network**。修改这些设置需要具有 `admin:*` 权限的管理会话；内置 `consoleAdmin` 策略包含该权限。

本页描述当前已实现的功能。部署示例见 [网络部署](deployment/network.md)，接口字段和错误码见 [网络配置 API](api/network-settings.md)。

## 先区分四种地址

| 地址 | 谁使用 | 示例 |
|---|---|---|
| S3 监听地址 | ZigFS 进程绑定网卡和端口，S3 与 Management API 共用 | `0.0.0.0:9000` |
| Admin 监听地址 | Go Admin/BFF 进程提供网页和 `/api/v1` 接口 | `0.0.0.0:9001` |
| BFF 连接 ZigFS 的地址 | BFF 进程访问 ZigFS | `http://127.0.0.1:9000` |
| Public URL | 浏览器和 S3 客户端访问对象服务；生成预签名上传、下载链接 | `https://s3.example.com` |

页面的 **Current Access URL** 是浏览器当前访问后台的地址，仅作展示。经过代理时，它通常与 Admin 监听地址不同。

`0.0.0.0` 表示监听所有 IPv4 网卡，不是供客户端访问的域名。`127.0.0.1` 表示访问者自己的机器：它可以用于同机 BFF 的上游地址，但不能作为远程浏览器的 Public URL。

## 配置项与生效方式

| 配置项 | 默认值或来源 | 校验与限制 | 生效方式 |
|---|---|---|---|
| S3 监听地址及端口 | `ZIGFS_API_ADDRESS`，默认 `0.0.0.0:9000` | IPv4/IPv6 字面地址；端口 1–65535 | 保存后重启 ZigFS |
| Admin 监听地址及端口 | `ZIGFS_ADMIN_LISTEN`，默认 `:9001` | IP 地址；端口 1–65535；空主机沿用 Go 的监听语义 | 保存后重启 Admin |
| BFF 上游地址 | `ZIGFS_ENDPOINT`，默认 `http://127.0.0.1:9000` | HTTP(S) origin，不含路径、凭证、查询参数或片段 | 随监听配置保存；旧地址无法建立连接时尝试新地址 |
| Public URL | `ZIGFS_S3_PUBLIC_ENDPOINT`，默认 `http://127.0.0.1:9000` | HTTP(S) origin，最长 2048 字节，不含路径、凭证、查询参数或片段 | 保存后即时生效 |
| Virtual Hosted Addressing | `ZIGFS_S3_VIRTUAL_HOSTED_STYLE`，默认关闭 | 开启时使用域名，不能使用 IP 地址 | 保存后即时生效 |
| Trusted Proxies | 默认空列表 | IPv4、IPv6 或 CIDR；每行一项，最多 64 项，每项最长 64 字节 | 保存后即时生效 |

保存不会自动停止或重启服务。界面会显示当前生效地址、待生效地址及需要重启的进程。

## 设置 Public URL

1. 确认浏览器可以访问目标 S3 地址。
2. 在 **Public URL** 填写完整的协议、主机和可选端口，例如 `http://192.0.2.10:9000` 或 `https://s3.example.com`。
3. 选择寻址方式，点击该区域的 **保存配置**。
4. 新生成一次上传或下载链接，确认链接的主机和协议正确。

填写 origin 时不要附加 `/` 或其他路径。保存只进行配置校验，不检测 DNS、证书、代理或服务连通性。

新生成的链接立即使用新配置；已有链接不会被重写。切换域名或寻址模式可能使旧链接失效，客户端应重新获取链接。Public URL 使用 HTTPS 不会让 ZigFS 的 HTTP 监听器自动启用 TLS。

## 选择 S3 寻址方式

以 Bucket `photos`、对象 `image.jpg` 为例：

| 模式 | 示例 |
|---|---|
| Path-style，关闭虚拟主机寻址 | `https://s3.example.com/photos/image.jpg` |
| Virtual-hosted-style，开启虚拟主机寻址 | `https://photos.s3.example.com/image.jpg` |

本机开发和直接使用 IP 的部署应使用 Path-style。

开启 Virtual-hosted-style 前，需要准备：

- `s3.example.com` 及 Bucket 子域名的 DNS 解析，通常使用 `*.s3.example.com`。
- 能处理这些 Host 的代理路由。
- 覆盖实际访问域名的 HTTPS 证书。
- 保留客户端原始 Host 的转发配置，避免破坏 S3 签名校验。

含点的 Bucket 名称会产生多级子域名，普通 `*.s3.example.com` 证书通常不能覆盖；应使用适配的证书或 Path-style。

## 设置可信代理

当客户端经过 Nginx、负载均衡器或 BFF 时，ZigFS 直接观察到的是代理的连接地址。Trusted Proxies 指定哪些连接来源可以提供可信的客户端 IP 和协议。

示例，每行一项：

```text
127.0.0.1
10.0.0.0/24
::1
```

只填写实际受控的代理地址或网段。使用 BFF 时，应包含 **ZigFS 观察到的 BFF 连接地址**；代理和 BFF 不在同一台机器上时，这通常不是 `127.0.0.1`。

保存后，解析结果用于：

- IAM 的 `aws:SourceIp` 条件。
- IAM 的 `aws:SecureTransport` 条件。
- 审计日志的 `request.source_ip`。

### 解析规则

1. 如果 TCP 对端不在可信列表中，忽略转发头，使用实际连接 IP，按当前 HTTP 监听器将安全传输状态视为 `false`。
2. 对可信对端，解析 `X-Forwarded-For`，从右向左越过可信代理，遇到第一个不可信节点即停止。
3. `X-Forwarded-Proto` 必须与 IP 链逐项对齐，每项为 `http` 或 `https`；使用选中节点对应的协议。
4. 重复、非法或过长的 IP 转发链回退到连接对端；缺失、重复、非法或数量不匹配的协议头不会声明 HTTPS。

BFF 会追加自己观察到的连接 IP 和协议，不会直接使用浏览器声明的 IP 作为身份。当前不解析 RFC `Forwarded` 和 `X-Real-IP`。

清空列表并保存可立即关闭转发头信任。不要仅因为 Public URL 是 HTTPS 就假定 `aws:SecureTransport` 为 `true`，该条件取决于可信链的协议判断。

## 修改监听地址和端口

1. 在监听配置区域填写 S3、Admin 的目标地址和端口。IPv6 主机输入不需要方括号，页面会组装成 `[::1]:9000`。
2. 核对 **BFF 连接 ZigFS 的地址**。它会随 S3 地址更新；远程部署或代理部署应改成 BFF 实际可达的地址。
3. 保存配置。系统在 ZigFS 主机检查 S3 监听，在 BFF 主机检查 Admin 监听。
4. 核对页面的待生效地址和重启提示。
5. 通过现有启动脚本或进程管理器，手动重启提示的服务。
6. Admin 端口改变后，使用新地址打开后台，或更新反向代理的上游。
7. 刷新配置，确认当前地址已更新、对应重启提示消失，并验证一次上传下载。

S3 端口改变不会自动修改 Public URL、DNS、容器端口映射或代理上游。请按实际部署同步调整。

### BFF 如何保持连接

保存前，BFF 先持久化当前地址和新地址，之后再提交 ZigFS 的监听配置。旧地址无法建立连接时，BFF 尝试新地址，并在成功后使用新地址。因此可以先重启 Admin，也可以先重启 ZigFS。

这不是无中断迁移：服务重启期间请求仍可能失败。只有尚未建立连接的失败才会尝试另一个地址；HTTP 错误、TLS 错误或响应中断不会触发已经发送的写请求重放。

### 端口检查的边界

不同端口会进行实际绑定探测。同端口更换网卡地址时，为避免与自身正在运行的监听器冲突，探测使用临时端口检查网卡可用性。正式启动仍会再次绑定目标端口。

保存与重启之间，其他进程仍可能占用端口；保存成功不是未来绑定成功的保证。

## 持久化与配置优先级

下表的 `data` 指 `ZIGFS_DATA_ROOT`，不是固定目录名。

| 文件 | 内容 | 管理进程 |
|---|---|---|
| `data/.zigfs/config/network.json` | Public URL、寻址模式、可信代理 | ZigFS |
| `data/.zigfs/config/listener.json` | 下一次启动的 S3 监听地址 | ZigFS |
| `ZIGFS_ADMIN_CONFIG` 指定的文件 | Admin 监听地址及 ZigFS 上游候选地址 | BFF |

优先级如下：

- ZigFS 启动默认值、`.env`、进程环境变量和命令行先确定基础配置；持久化的监听覆盖值在启动绑定前应用。
- `network.json` 中的 Public URL 和寻址模式优先于对应 `.env` 值；没有该文件时使用启动配置。
- BFF 保存值优先于 `ZIGFS_ADMIN_LISTEN`、`ZIGFS_ENDPOINT`；没有保存文件时使用环境变量及内置默认值。
- 老版本 `network.json` 未包含可信代理字段时，按空列表处理。

BFF 默认保存到操作系统用户配置目录下的 `zigfs-admin/listener.json`，由运行 BFF 的系统账号决定。部署时建议显式设置：

```bash
export ZIGFS_ADMIN_CONFIG=/var/lib/zigfs-admin/listener.json
```

该目录必须对 BFF 可写；容器部署需要持久化挂载。BFF 不读取或写入 ZigFS 的数据目录。

## 故障排查

| 现象 | 排查方式 |
|---|---|
| 后台能打开，但上传下载失败 | 查看预签名 URL；确认 Public URL 能从浏览器访问，未误用本机回环地址 |
| 开启虚拟主机模式后访问失败 | 检查 Bucket 子域名 DNS、证书覆盖范围、代理 Host 保留方式 |
| 保存提示端口不可用 | 检查目标主机是否有该网卡、端口是否被占用、进程是否有绑定权限 |
| 保存后仍显示旧端口 | 查看待生效值，手动重启对应进程，再刷新页面 |
| 修改 `.env` 或环境变量没有效果 | 检查是否存在优先级更高的持久化覆盖文件 |
| BFF 重启后仍无法连接 | 确认新上游地址从 BFF 主机可达；检查监听绑定、容器映射、防火墙和代理配置 |
| 审计 IP 仍是代理 IP | 检查实际 TCP 对端是否可信，以及链路中是否还有未配置的代理 |
| HTTPS 访问仍不满足安全传输策略 | 检查可信代理及 `X-Forwarded-Proto` 与 IP 链是否逐项对齐 |
| 提示“部分监听配置已保存” | 刷新并核对两端保存值；修复 BFF 配置存储问题后再提交，避免盲目重启 |

### 无法通过页面恢复时

1. 保留当前配置副本，停止需要恢复的进程。
2. 恢复该进程的部署默认配置，确认地址可用。
3. 将对应覆盖文件移动到备份位置：恢复 S3 监听使用 `listener.json`；恢复公开访问和代理配置使用 `network.json`；恢复 BFF 使用 `ZIGFS_ADMIN_CONFIG` 对应文件。
4. 重启并检查 `/health/ready`，随后重新登录后台核对配置。

恢复网络配置不需要删除 Bucket、对象、密钥或其他元数据。无法读取或解析的配置文件不会被静默忽略，应修复文件或按上述流程恢复。

## 当前范围

已支持配置保存、即时生效项、重启生效项、可信代理判断、审计操作分类及多语言错误提示。自动重启、自动配置 DNS、签发证书、配置防火墙和反向代理不属于当前功能。
