# Web 对象操作授权

Web 对象页面使用当前登录会话授权，不读取 AK 列表，也不自动选择其他用户的 AK。部署管理员和具有对应 S3 权限的管理员用户，无需创建 AK/SK 即可上传、下载、复制、移动、删除及编辑对象标签。普通用户仍受当前 IAM 策略限制，服务端拒绝无权限的请求。

`POST /_admin/v1/objects/presign`（BFF 为 `/api/v1/objects/presign`）的 `access_key` 可省略或留空。接口检查目标操作以及复制源的权限，生成标准 SigV4 请求链接。内部固定签名标识不是持久化的访问密钥，不出现在 AK 列表，也不能用于自行签名。

短期链接的安全令牌使用 AES-256-GCM 包装登录会话和到期时间；签名密钥仅在服务端派生，不返回浏览器。SigV4 绑定请求方法、路径、查询参数以及复制源头部。链接到期不晚于登录会话到期，使用时重新验证会话、用户状态和最新策略，并沿用 S3 数据面的资源策略、KMS 和对象检查。修改路径、方法或签名参数会使授权失效。审计认证类型为 `management_session`，保留实际用户身份。

兼容显式传入 `access_key` 的旧调用，但同时要求当前登录用户和指定 AK 都有相应权限。直接使用 S3 API 的外部客户端继续使用原有 AK/SK/STS 认证。

验证：`python3 conformance/console_session_objects.py`，覆盖无 AK 的管理员操作、分片上传、复制、标签、只读权限、签名篡改、会话失效及过期。

## 浏览器原生下载

当前对象、历史版本及批量下载使用 `download: true` 的 GET 签名链接，ZigFS 将标准 `response-content-disposition=attachment` 查询参数纳入 SigV4 签名并返回附件响应头。`download` 不能用于 PUT、DELETE 或 tagging；`version_id` 可同时提供。普通预览链接不添加附件响应头。

页面不再通过 `fetch(...).blob()` 等待完整对象，也不显示阻塞式下载加载框。签名成功后立即将链接交给浏览器下载管理器，提示“已开始下载”，不声称文件已保存完成。ZigFS 沿用流式 GET、Content-Length 与 Range，文件传输不经过 BFF。浏览器管理临时文件及完成后的保存，例如 Chromium 的 `.crdownload`；网页不指定临时扩展名。跨域下载依赖服务端附件响应头，不能仅依赖 `<a download>`。

下载请求仍受当前登录权限、签名到期及 KMS 授权约束。已开始的响应持续流式传输；若中断后需要发起新的 Range 请求，而原链接已过期，则需重新生成链接。多文件下载受浏览器的自动下载许可控制。

验证包括真实 ZigFS 的附件响应头、普通 GET 不受影响、指定版本、Range、签名篡改和响应头注入拒绝，以及 Chrome 中跨域下载在响应体尚未结束时就触发下载、中文文件名正确且 Admin 页面保持打开。浏览器验证使用受控的小文件响应，不代表已进行 40 GB 完整下载压测。
